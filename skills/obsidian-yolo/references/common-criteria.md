# 공통 한국어 검토 기준

## 기준 체계

| 코드 | 영역 |
|---|---|
| `PRES` | 원문·정보 보존 |
| `NORM` | 어문 규범과 표기 |
| `VERIFY` | 어문 규범 확인과 사실 확인의 구분 |
| `SENT` | 문장 성립과 호응 |
| `LEX` | 어휘와 표현 선택 |
| `EASY` | 이해 용이성 |
| `REL` | 상황·관계·높임 적합성 |
| `FLOW` | 문단과 담화 흐름 |
| `VOICE` | 작성자 문체와 일관성 |
| `AIPAT` | 한국어 인공지능 문체 |
| `FORMAT` | 문서 형식 |

---

## 1. 원문·정보 보존 (`PRES`)

### 반드시 보존

- 사실과 사건의 순서
- 인물, 조직, 장소, 제품, 프로젝트 이름
- 날짜, 시간, 수치, 단위, 버전
- 조건, 예외, 범위
- 긍정과 부정
- 가능, 권고, 의무, 확정의 차이
- 원인과 결과
- 비교 대상과 비교 방향
- 출처와 인용 관계
- 작성자의 의견과 인용자의 의견 구분

### 검사 항목

- 요약하면서 핵심 조건을 누락하지 않았는가.
- 가능성을 확정 사실로 바꾸지 않았는가.
- 비판을 중립적 설명으로 약화하거나, 중립적 설명을 비판으로 강화하지 않았는가.
- 원문에 없던 해석, 결론, 이유를 추가하지 않았는가.
- 인용문과 작성자 서술을 섞지 않았는가.
- 전문 용어를 쉬운 말로 바꾸면서 의미 범위를 좁히거나 넓히지 않았는가.

의미 보존 실패는 `BLOCK`입니다.

---

## 2. 어문 규범과 표기 (`NORM`)

### 검사 항목

- 한글 맞춤법
- 띄어쓰기
- 표준어
- 외래어 표기
- 로마자 표기
- 문장 부호
- 숫자와 단위 표기
- 괄호와 조사 연결
- 고유명사 표기 일관성
- 오탈자와 중복 문자

### 적용 원칙

- 공식 규범이나 사전 용례를 확인할 수 있는 도구가 있으면 해당 근거를 확인합니다.
- 확인 도구가 없거나 표준어·띄어쓰기·외래어 표기가 불확실하면 임의로 확정하지 않고 `REVIEW`로 남깁니다.
- 문장 내부에서 명백하게 확인되는 오탈자, 조사·어미 오류와 호응 오류는 도구가 없어도 수정할 수 있습니다.
- 전문 분야에서 정착한 표기가 공식 표기와 다를 때는 문서 목적과 독자를 확인합니다.
- 제품명과 서비스명은 일반 명사 표기 규칙으로 임의 교정하지 않습니다.
- 대본의 발음 표기는 일반 문서의 맞춤법과 별도로 판단합니다.

명백한 표기 오류는 `FIX`, 근거 확인이 필요하거나 전문 분야 관행과 충돌하면 `REVIEW`입니다.

---

## 3. 어문 규범 확인과 사실 확인의 구분 (`VERIFY`)

문장 교정과 사실 검증을 같은 작업으로 취급하지 않습니다.

### 어문 규범 확인

- 맞춤법, 표준어, 띄어쓰기, 외래어 표기와 사전 용례를 확인하는 작업입니다.
- 확인 도구가 있으면 공식 규범이나 신뢰할 수 있는 사전을 우선합니다.
- 확인할 수 없고 판단이 불확실하면 원문을 보존하고 `REVIEW`로 남깁니다.
- 문체 취향을 규범 오류처럼 단정하지 않습니다.

### 사실 확인

- 날짜, 수치, 인물, 제품 사양, 사건, 법령, 버전과 외부 주장 등의 진위를 확인하는 작업입니다.
- 사용자가 사실 확인을 요청했거나 작업에 필요한 확인 도구와 출처가 있을 때만 별도로 수행합니다.
- 문장이 자연스럽다는 이유로 사실까지 맞다고 판단하지 않습니다.
- 외부 정보와 원문이 충돌하더라도 사용자의 요청 없이 조용히 사실을 바꾸지 않습니다.
- 사실을 확인할 수 없으면 원문의 주장 수준을 유지하고 불확실성을 표시합니다.

### 적용 우선순위

1. 원문의 사실·조건·확신 정도를 보존합니다.
2. 어문 규범상 명백한 오류만 수정합니다.
3. 확인이 필요한 규범 문제와 사실 문제를 서로 구분해 표시합니다.
4. 사실 검증이 포함되면 근거와 수정 이유를 문장 교정 결과와 분리합니다.

사실·조건을 임의로 바꾸면 `BLOCK`, 불확실한 규범을 단정하면 `REVIEW`입니다.

---

## 4. 문장 성립과 호응 (`SENT`)

### 3.1 주어·서술어 호응

- 주어와 서술어가 의미상 맞는가.
- 주제가 바뀌었는데 이전 서술어에 연결되지 않았는가.
- 명사형 제목을 완결문처럼 처리하지 않았는가.

### 3.2 목적어·서술어 호응

- 목적어가 서술어가 요구하는 대상과 맞는가.
- ‘접근성이 어렵다’, ‘효과를 강화하다’처럼 결합이 어색하지 않은가.

### 3.3 접속의 대등성

- `및`, `또는`, `-고`, `-거나`로 연결한 성분의 문법적 크기와 의미가 대등한가.
- 명사와 문장, 행위와 결과를 억지로 병렬하지 않았는가.

### 3.4 생략

- 한국어에서 자연스러운 주어 생략은 유지합니다.
- 필요한 조사, 목적어, 기준, 행위 주체가 빠져 의미가 불분명할 때만 보완합니다.
- 영어식으로 모든 문장에 주어를 반복해 넣지 않습니다.

### 3.5 조사와 어미

- `로서/로써`, `에/에게`, `을/를`, `이/가`, `은/는`이 의미에 맞는가.
- 연결 어미가 앞뒤 관계를 정확히 나타내는가.
- 시제와 높임 선어말 어미가 일관되는가.

### 3.6 수식 범위

- 긴 관형절이 어느 명사를 꾸미는지 분명한가.
- 부사어의 적용 범위가 모호하지 않은가.
- 부정 표현이 어느 성분을 부정하는지 분명한가.

### 3.7 지시 대상

- `이것`, `그것`, `해당`, `이러한`, `앞서`가 가리키는 대상이 분명한가.
- 동일 문단에 가능한 대상이 여러 개라면 명사를 다시 씁니다.

문장 구조로 의미가 달라지면 `BLOCK`, 명백한 호응 오류는 `FIX`입니다.

---

## 5. 어휘와 표현 선택 (`LEX`)

### 검사 항목

- 문맥에 맞는 어휘인가.
- 비슷한 단어를 혼동하지 않았는가.
- 한자어, 외래어, 고유어 중 독자에게 가장 적절한 표현인가.
- 같은 개념을 문서 안에서 다른 말로 부르지 않았는가.
- 추상 명사가 실제 행위나 결과를 가리지 않는가.
- `-적`, `-성`, `-화`, `-에 대한`, `-을 통해`가 필요 이상으로 겹치지 않는가.
- 동사로 쓸 수 있는 내용을 명사구로 길게 만들지 않았는가.

### 금지하지 않는 것

- 전문 용어
- 업계에서 통용되는 외래어
- 의도적인 한자어
- 정확한 의미를 가진 추상 명사

쉬운 말로 바꾸는 것보다 정확성이 우선입니다. 쉬운 대체어가 의미를 충분히 보존할 때만 바꿉니다.

---

## 6. 이해 용이성 (`EASY`)

### 검사 항목

- 대상 독자가 용어를 이해할 수 있는가.
- 약어는 처음 등장할 때 풀어 썼는가.
- 어려운 외국어와 한자어를 설명 없이 사용하지 않았는가.
- 한 문장에 조건과 예외가 과도하게 겹치지 않았는가.
- 핵심 정보가 문장 뒤에 지나치게 늦게 나오지 않는가.
- 독자가 행동해야 한다면 대상, 기한, 방법, 조건이 분명한가.
- 긴 문장은 의미 단위로 나누는 편이 나은가.
- 쉬운 말로 바꾸면서 전문적 정확성을 잃지 않았는가.

### 독자 기준

- 일반 대중
- 조직 내부 구성원
- 전문 분야 종사자
- 특정 프로젝트 참여자
- 영상이나 강의의 청중

독자를 알 수 없으면 일반 성인 독자를 기본으로 하되 전문 용어를 임의 제거하지 않습니다.

---

## 7. 상황·관계·높임 적합성 (`REL`)

높임법은 모든 상황에 하나의 답이 있는 규범으로 취급하지 않습니다. 상대, 관계, 매체와 조직 문화에 따라 판단합니다.

### 검사 항목

- 문서 전체의 종결 어미가 목적과 관계에 맞는가.
- `하십시오체`, `해요체`, `해체`, 서술형 문어체가 섞이지 않았는가.
- 주체 높임과 상대 높임이 구분되어 있는가.
- 사물이나 상품을 불필요하게 높이지 않았는가.
- `말씀`, `성함`, `연세` 등 높임 어휘가 대상에 맞는가.
- 직함과 `-님` 사용이 관계와 조직 관행에 맞는가.
- 요청문이 지나치게 명령적이거나 반대로 지나치게 우회적이지 않은가.
- 사과와 감사가 본문보다 길어지지 않았는가.

### 원칙

- 언어 예절 자료는 지침으로 활용하고 절대 규범처럼 강제하지 않습니다.
- 현대 사용 실태와 조직 관행을 함께 고려합니다.
- 사용자가 정한 존댓말 수준을 임의로 바꾸지 않습니다.

---

## 8. 문단과 담화 흐름 (`FLOW`)

### 검사 항목

- 한 문단이 하나의 중심 내용을 다루는가.
- 결론, 근거, 예시, 예외의 관계가 분명한가.
- 앞 문장을 다시 말하는 문장이 반복되지 않는가.
- 접속 부사 없이도 관계가 분명한데 `따라서`, `또한`, `한편`, `즉`을 반복하지 않는가.
- 제목과 본문 내용이 일치하는가.
- 목록의 항목 기준이 동일한가.
- 사실, 판단, 추정, 제안을 구분했는가.
- 독자가 필요한 순서로 정보가 배치되어 있는가.
- 결론이 여러 번 반복되지 않는가.

구조를 바꿀 때는 원래 강조 순서와 작성자의 의도를 보존합니다.

---

## 9. 작성자 문체와 일관성 (`VOICE`)

### 보존 항목

- 직설적이거나 완곡한 어조
- 단정과 유보의 정도
- 문장 길이와 호흡
- 의도적 반복
- 말줄임표, 괄호, 문장 부호의 개인적 사용
- 전문 용어와 고유 표현
- 유머, 반어, 비유
- 구어체와 문어체의 선택

### 검사 항목

- 작성자의 목소리를 일반적인 보고서 문체로 평준화하지 않았는가.
- 모든 문장을 같은 종결형과 길이로 만들지 않았는가.
- 수정자가 새로운 의견을 덧붙이지 않았는가.
- 사용자가 확정한 표현을 다시 바꾸지 않았는가.
- 문서 내부에서 용어와 말투가 불필요하게 흔들리지 않는가.

---

## 10. 문서 형식 (`FORMAT`)
- Markdown 제목 단계가 건너뛰지 않는가.
- 목록 깊이가 과도하지 않은가.
- 표가 문장보다 이해하기 쉬울 때만 사용했는가.
- 코드 블록, 인용문, 링크, 각주를 보존했는가.
- 문서 유형에 맞는 줄바꿈을 사용했는가.
- 원본의 태그, 속성, 내부 링크를 임의로 변경하지 않았는가.
