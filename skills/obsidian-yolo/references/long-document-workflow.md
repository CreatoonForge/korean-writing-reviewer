# Obsidian YOLO 긴 노트 처리 절차

볼트의 노트가 길거나 여러 제목·링크·임베드·쿼리·코드 블록을 포함할 때 적용합니다.

## 1. 긴 노트 판정

다음 중 하나에 해당하면 긴 노트로 취급합니다.

- 여러 개의 큰 제목과 하위 섹션이 있습니다.
- frontmatter, 내부 링크, 임베드, Dataview, 표와 코드가 많습니다.
- YOLO가 한 번에 전체 내용을 안전하게 읽기 어렵습니다.
- 여러 섹션에서 같은 용어·결정·링크를 공유합니다.
- 사용자가 섹션별 검토를 요청했습니다.

고정된 글자 수만으로 판정하지 않습니다.

## 2. 전체 구조 확인

편집 전에 YOLO의 파일 읽기·검색 도구로 가능한 범위에서 확인합니다.

- frontmatter와 Properties
- 제목과 하위 제목 구조
- 주 문서 유형과 보조 유형
- 내부 링크, 임베드, 블록 참조와 각주
- Dataview·Mermaid·코드·템플릿 영역
- 주요 용어와 표기
- 높임 수준과 문체
- 섹션 간 의존 관계

전체를 읽지 못하면 확인하지 못한 섹션을 추정하지 않습니다.

## 3. 섹션 분할

- 제목 단위 또는 의미가 완결되는 범위로 나눕니다.
- Callout, 표, 코드 블록, 임베드와 각주 정의 중간에서 나누지 않습니다.
- 제목 변경은 링크 앵커에 영향을 줄 수 있으므로 별도 요청이 없으면 피합니다.
- 같은 내부 링크나 용어가 여러 섹션에서 사용되는지 먼저 검색합니다.

## 4. 섹션별 편집

각 섹션을 다음 순서로 처리합니다.

1. `editor-protection.md`에 따라 보호 구문 잠금
2. 섹션의 목적과 독자 확인
3. 공통·유형별 기준 적용
4. 일반 자연어만 최소 수정
5. YOLO의 `obsidian-output-format` 규칙으로 해당 범위 편집
6. 링크·임베드·표·코드 구조 확인
7. 전체 노트의 용어·문체 기준 갱신

한 번의 편집 블록에 서로 떨어진 여러 섹션을 억지로 포함하지 않습니다.

## 5. 노트 전체 일관성 검사

모든 섹션을 수정한 뒤 다음을 다시 확인합니다.

- frontmatter와 Properties 무결성
- 제목 단계와 내부 링크 앵커
- 위키 링크, 임베드와 블록 참조
- Dataview 필드 이름과 쿼리
- 용어, 고유명사, 태그와 별칭
- 높임 수준, 시제와 종결형
- 중복된 결론과 상충하는 결정
- 각주·출처와 인용 관계
- 표의 수치와 본문 설명

섹션별 편집으로 링크나 쿼리 관계가 깨지면 해당 범위만 수정합니다.

## 6. 문맥 제한

- 읽지 않은 섹션의 내용을 추정하지 않습니다.
- 전체 노트를 확인하지 못했다면 전체 검토를 완료했다고 표현하지 않습니다.
- 현재 확인한 제목과 남은 범위를 알려 줍니다.
- 일부 섹션만 보고 전체 노트 점수를 계산하지 않습니다.
- 다른 노트의 내용이 필요하면 사용 가능한 볼트 검색으로 확인하고, 찾지 못하면 추정하지 않습니다.

## 7. 점수 평가

- 점수 평가 조건이 충족된 경우에만 점수표를 읽습니다.
- 전체 노트를 다시 확인할 수 있을 때만 주 유형의 최종 점수를 계산합니다.
- 섹션별 점수를 평균해 전체 점수로 만들지 않습니다.
- 점수를 높이기 위해 링크, 메모의 압축성이나 사용자가 확정한 문장을 바꾸지 않습니다.

## 8. 완료 검증

- 모든 편집이 지정된 섹션 안에 있습니다.
- YOLO 편집 출력 규칙을 따랐습니다.
- Obsidian 고유 구문과 렌더링 구조가 보존되었습니다.
- 노트 전체의 용어와 말투가 일관됩니다.
- 읽지 못한 범위를 완료한 것처럼 주장하지 않았습니다.
