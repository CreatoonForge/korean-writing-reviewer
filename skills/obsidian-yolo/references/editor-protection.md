# Obsidian YOLO 파일·구문 보호 규칙

Obsidian 볼트의 Markdown 파일을 YOLO로 수정할 때 적용합니다. 기존 파일 편집 출력은 YOLO의 `obsidian-output-format` 스킬에 위임하며, 이 문서에서 DSL 형식을 다시 정의하지 않습니다.

## 1. 편집 범위

- 사용자가 선택하거나 지정한 문단·섹션만 수정합니다.
- 가능한 한 식별 가능한 최소 범위를 교체합니다.
- 파일 전체 재작성은 사용자가 명시적으로 요청했거나 최소 편집으로 안전하게 처리할 수 없을 때만 수행합니다.
- YOLO가 제공하는 파일 읽기·검색·편집 도구와 `obsidian-output-format` 규칙을 따릅니다.
- 문장 검토를 파일 이동, 삭제, 이름 변경과 혼합하지 않습니다.

## 2. YAML frontmatter와 Properties

사용자가 속성 편집을 요청하지 않았다면 frontmatter 전체를 보호합니다.

- 시작·종료 경계 `---`
- 속성 이름과 순서
- 들여쓰기와 배열 구조
- 날짜, 별칭, CSS 클래스, 태그와 상태
- 따옴표, 다중 행 값과 템플릿 값

본문 교정 과정에서 frontmatter 값을 자연어처럼 고치지 않습니다.

## 3. Obsidian 링크와 임베드

다음 구문을 하나의 보호 토큰으로 취급합니다.

- `[[문서]]`
- `[[문서|표시 이름]]`
- `[[문서#제목]]`
- `[[문서#제목|표시 이름]]`
- `[[문서^block-id]]`
- `![[문서]]`
- `![[파일#제목]]`
- Markdown 링크와 이미지 링크
- 블록 참조 식별자 `^block-id`

표시 이름의 교정을 요청받아도 문서명, 제목 앵커, 블록 식별자와 임베드 기호를 보존합니다.

## 4. Callout·각주·체크박스

- Callout 헤더 `> [!type]`, 접기 기호와 제목
- Callout 내부의 인용 깊이
- 각주 참조 `[^id]`와 정의 `[^id]:`
- 체크박스 상태 `[ ]`, `[x]`, `[-]`와 중첩 들여쓰기
- 작업의 완료 상태, 날짜와 식별자

문장을 다듬으면서 callout 구조, 각주 연결과 작업 상태를 바꾸지 않습니다.

## 5. Dataview·템플릿·코드

다음은 일반 문장 교정 대상에서 제외합니다.

- `dataview`, `dataviewjs` 코드 블록
- Dataview 인라인 필드와 쿼리
- Mermaid 코드 블록
- 기타 코드 블록과 인라인 코드
- Templater, Templates와 플러그인 변수
- HTML·JSX·MDX 태그
- 주석, 정규식, 명령어와 파일 경로

코드 블록 주변의 설명만 수정하고 코드 펜스, 언어 식별자와 내부 코드를 유지합니다.

## 6. Markdown 표·목록·줄바꿈

- 표의 파이프 수, 정렬 행과 셀 대응을 유지합니다.
- 목록 기호와 중첩 깊이를 유지합니다.
- Obsidian에서 의미가 있는 두 칸 강제 줄바꿈을 보존합니다.
- 빈 줄, 들여쓰기와 인용 깊이를 임의로 정리하지 않습니다.
- 제목을 바꾸면 내부 링크와 임베드의 제목 앵커가 깨질 수 있으므로 사용자가 요청하지 않았다면 유지합니다.

## 7. 수정 가능한 영역

다음 조건을 충족하는 일반 한국어 문장만 교정합니다.

- 보호 구문 밖에 있습니다.
- 사용자가 수정 대상으로 지정했습니다.
- 링크·블록·쿼리·템플릿 관계를 바꾸지 않습니다.
- 앞뒤 문맥과 작성자의 의도를 확인할 수 있습니다.

## 8. 최종 검증

- frontmatter와 Properties가 동일합니다.
- 내부 링크, 임베드, 제목 앵커와 블록 참조가 유효한 형태입니다.
- Callout, 각주와 체크박스 연결이 유지됩니다.
- Dataview, Mermaid, 코드 블록과 템플릿이 변경되지 않았습니다.
- 표의 열 수, 목록 깊이와 줄바꿈 방식이 유지됩니다.
- YOLO 편집 출력이 `obsidian-output-format` 규칙과 충돌하지 않습니다.
