# 한국어 문장 검토 사례

사례는 정답 문장 모음이 아니라 판정 경계를 보여 주기 위한 참고 자료다. 실제 수정에서는 문서 유형과 작성자 의도를 우선한다.

## 1. 번역투와 동사 선택

### 원문

이 기능은 사용자가 파일을 보다 효율적으로 관리할 수 있도록 지원합니다.

### 검토

- `지원합니다`가 구체적인 기능을 가린다.
- 기능의 실제 행위가 파일 관리인지 자동 분류인지 확인해야 한다.

### 수정 예

이 기능은 사용자가 파일을 더 쉽게 관리하도록 돕습니다.

기능이 자동 분류라면 다음처럼 더 구체적으로 쓴다.

> 이 기능은 파일을 자동으로 분류해 관리를 단순화합니다.

### 판정

`REVIEW`. 기능을 모르면 임의로 구체화하지 않는다.

---

## 2. 과도한 명사화

### 원문

설정 변경에 대한 검토를 진행한 뒤 적용을 수행합니다.

### 수정

설정 변경을 검토한 뒤 적용합니다.

### 판정

`FIX`. 두 행위를 명사형과 포괄 동사로 겹쳐 썼다.

---

## 3. 자연스러운 주어 생략

### 원문

설치가 끝나면 프로그램을 다시 실행합니다.

### 잘못된 수정

사용자는 설치가 끝나면 사용자가 프로그램을 다시 실행합니다.

### 판정

원문 `KEEP`. 한국어에서 행위자가 문맥상 분명하므로 주어를 반복할 필요가 없다.

---

## 4. 피동문 유지

### 원문

설정 파일은 애플리케이션 시작 시 로드됩니다.

### 판정

`KEEP`. 처리 결과와 시점이 핵심인 기술 문장이다. 행위자를 억지로 추가하지 않는다.

---

## 5. 의미 없는 수동 표현

### 원문

회의에서 일정 변경이 결정되었습니다.

### 검토

회의록에서 결정 주체와 합의 여부가 중요할 수 있다.

### 수정 예

프로젝트 팀은 회의에서 일정을 변경하기로 결정했습니다.

### 판정

주체가 확인되면 `FIX`, 확인되지 않으면 `REVIEW`. 주체를 추정하지 않는다.

---

## 6. 사물 높임

### 원문

주문하신 상품은 품절이십니다.

### 수정

주문하신 상품은 품절입니다.

### 판정

`FIX`. 높임의 대상이 사람이 아니라 상품 상태에 잘못 연결되었다.

---

## 7. 높임 수준 유지

### 원문

자료 확인 부탁드립니다.

### 잘못된 수정

자료를 확인해 주시면 대단히 감사드리겠습니다.

### 판정

원문 `KEEP`. 업무 메시지로 충분히 정중하며, 과도하게 우회할 이유가 없다.

---

## 8. 긴 관형절의 수식 범위

### 원문

어제 검토한 오류가 발생한 설정 파일을 삭제했습니다.

### 문제

`어제 검토한` 대상이 오류인지 설정 파일인지 모호하다.

### 수정 예

어제 검토했던 설정 파일에서 오류가 발생해 해당 파일을 삭제했습니다.

### 판정

문맥에 따라 `BLOCK` 또는 `FIX`. 의미를 확인하지 않고 임의로 문장 구조를 정하지 않는다.

### 잘못된 수정

### 판정

잘못된 수정은 `BLOCK`. 확신 정도가 달라졌다.

### 판정

원문 `KEEP`. 개인 작업 메모의 압축성과 식별자를 보존한다.
