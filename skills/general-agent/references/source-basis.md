# 기준 근거와 활용 범위

이 문서는 스킬 설계에 사용한 근거를 정리합니다. 원문을 저장소에 복제하지 않고, 기준을 독자적인 문장으로 재구성합니다.

## 1. 한국어 어문 규범

### 활용 기준

- 한글 맞춤법
- 표준어 규정
- 외래어 표기법
- 국어의 로마자 표기법

공식 규범은 표기 정확성의 기준으로 사용합니다.

공식 누리집:
- https://korean.go.kr/kornorms/main/main.do

## 2. 국립국어원 공공언어 평가

2025년 공공기관 등 공문서 평가 설명회에서는 평가의 큰 기준을 `용이성`과 `정확성`으로 구분합니다.

- 용이성: 어려운 외국어·외래어와 외국 문자, 일반 국민이 이해하기 어려운 표현
- 정확성
  - 표기의 정확성: 어문 규범
  - 표현의 정확성: 호응, 접속, 생략, 조사·어미, 어휘

이 분류는 업무 보고서·공공 문서 프로필의 기본 근거로 사용합니다. 범용 한국어 문서 전체에 그대로 적용하지는 않습니다.

공식 자료:
- https://www.korean.go.kr/front/board/boardMovieView.do?b_movie_type=&b_seq=256&board_id=16&mn_id=234&pageIndex=1

## 3. 방송언어 가이드라인

첨부 자료에서 다음 원칙을 활용했습니다.

- 정확하고 이해하기 쉬운 표현
- 우리말 대체어가 있는 외국어 사용의 신중함
- 맞춤법과 띄어쓰기
- 인터뷰 요약·번역 시 왜곡과 첨언 방지
- 편집·누락 시 전체 발언 취지 보존
- 외신 번역투 방지
- 매체와 장르에 맞는 언어 사용

이 자료는 대본, 설명문, 정보 전달 문서의 기준에 반영합니다.

원문 PDF는 배포 파일에 포함하지 않습니다.

## 4. 표준 언어 예절

첨부 자료에서 다음 원칙을 활용했습니다.

- 하십시오체를 예시 기준으로 사용하더라도 상대에 따라 종결 어미를 조정할 수 있음
- 직장과 일상에서 관계에 따른 높임 사용
- 호칭과 지칭은 상황에 따라 달라짐

다만 표준 언어 예절은 강제 규범이 아니라 언어 예절 지침으로 취급합니다. 국립국어원은 이후의 언어 변화를 반영한 `우리, 뭐라고 부를까요?`를 함께 참고하도록 안내하고 있습니다.

공식 자료:
- https://www.korean.go.kr/front/etcData/etcDataView.do?etc_seq=648&mn_id=208&pageIndex=1

해당 자료는 공공누리 제4유형이므로 원문을 변형하거나 저장소에 재배포하지 않습니다. 내용은 일반 원칙을 확인하는 참고 자료로만 사용합니다.

## 6. 기준 설계에서 독자적으로 추가한 영역

다음은 공식 자료의 평가표를 복사한 것이 아니라 실제 범용 스킬 운영을 위해 새로 설계한 영역입니다.

- 원문·정보 보호
- 문서 유형 자동 판정
- 기술 문서의 코드와 설정 보호
- 개인 메모와 Obsidian 노트의 압축성 보존
- 한국어 생성형 인공지능 문체 패턴
- 작성자 목소리와 확정 표현 보존
- 혼합 문서의 주 유형·보조 유형 적용
- `BLOCK`, `FIX`, `REVIEW`, `KEEP` 판정 체계

## 7. 점수 체계의 설계 범위

점수 평가 방식은 공식 자료의 평가표를 복제한 것이 아니라, 한국어 결과물의 품질을 문서 목적에 맞게 다시 검증하기 위해 독자적으로 설계했습니다.

공통 구조:

- 필수 통과 조건 `G1–G7`
- `A / B / C / D / F` 등급
- 100점 총점
- 85점 기본 통과점
- 유형별 필수 하한
- 한 차례 재수정 제한
- 짧거나 문맥이 부족한 글의 점수 생략

지원 유형:

- 대본
- 업무 보고서·공공 문서
- 기술 문서
- 이메일·메시지
- 개인 메모·지식 노트
- 조사·학습 자료
- 회의록·프로젝트 기록
- 게시글·댓글
- 일반 설명문·교육 자료

평가 항목과 배점은 유형별 목적에 따라 다릅니다. 한 유형의 점수표를 다른 유형에 그대로 적용하지 않습니다.

## 8. 규범 확인과 사실 확인

이 스킬은 어문 규범 확인과 사실 확인을 서로 다른 작업으로 취급합니다.

- 어문 규범 확인: 맞춤법, 표준어, 띄어쓰기, 외래어 표기와 사전 용례
- 사실 확인: 날짜, 수치, 사건, 법령, 버전, 제품 사양과 외부 주장

실행 환경에 공식 규범·사전·검색 도구가 있으면 확인할 수 있습니다. 도구가 없거나 근거가 불충분하면 불확실한 표기와 사실을 임의로 수정하지 않고 `REVIEW`로 남깁니다.

문장 교정 요청만 받은 경우 원문의 사실을 조용히 교체하지 않습니다. 사용자가 사실 검증을 요청하거나 외부 근거를 확인할 수 있을 때만 별도 검증을 수행합니다.

## 9. 배포 환경 분리

저장소는 같은 한국어 검토 기준을 두 개의 독립 설치본으로 제공합니다.

- `skills/general-agent/`: Claude Code, Codex, Hermes와 VS Code 기반 에이전트 등 일반 Agent Skills 환경
- `skills/obsidian-yolo/`: Obsidian YOLO 환경

공통 기준과 점수표는 두 설치본에 각각 포함합니다. 실행 방식, 파일 편집 규칙과 보호 구문은 환경별 `SKILL.md`, `editor-protection.md`, `long-document-workflow.md`에서 분리합니다.

## 10. 평가와 개선의 분리

점수 체계는 현재 문서 평가와 개선 후 검증을 모두 지원하지만 두 작업을 섞지 않습니다.

- `evaluate`: 현재 원문을 그대로 평가
- `improve`: 점수 없이 수정
- `evaluate-and-improve`: 원문 평가 후 수정본 재평가

평가만 요청한 경우 원문이나 파일을 변경하지 않습니다. 개선이 요청된 경우에도 원문 점수를 먼저 확정한 뒤 수정하며, 수정본의 결과를 보고 원문 점수를 소급 변경하지 않습니다.
