# 품질 평가 공통 규칙

## 1. 목적

점수는 현재 문서의 품질 상태를 확인하고, 개선이 요청된 경우 취약한 항목을 찾기 위한 기준이다.

- 문서나 작성자를 서열화하지 않는다.
- 정밀한 객관 측정값처럼 표현하지 않는다.
- 평가 전에 평가 대상을 고정한다.
- 원문 점수와 수정본 점수를 구분한다.
- 평가만 요청한 경우 점수와 개선점을 제시하되 문서를 수정하지 않는다.
- 점수를 높이기 위해 정보, 감정, 말투와 압축성을 훼손하지 않는다.
- 문서 유형에 맞는 평가표 하나만 사용한다.

## 2. 작업 모드 우선

점수 관련 작업을 시작하기 전에 `evaluation-workflow.md`에서 다음 모드 중 하나를 정한다.

| 모드 | 점수 | 수정 | 재평가 |
|---|---:|---:|---:|
| `evaluate` | 현재 원문 평가 | 하지 않음 | 없음 |
| `improve` | 계산하지 않음 | 최소 수정 | 없음 |
| `evaluate-and-improve` | 원문 먼저 평가 | 한 차례 개선 | 수정본 재평가 |

평가 요청만으로 `evaluate-and-improve`를 선택하지 않는다.

## 3. 점수표를 읽는 조건

다음 경우에만 이 문서와 유형별 점수표를 읽는다.

- 점수, 등급 또는 품질 평가를 명시적으로 요청함
- 제출·출판·배포 전 평가나 최종 검수를 요청함
- 둘 이상의 문서나 수정본을 비교함
- 회귀 검증, 품질 자동화 또는 평가 기준 시험임
- 평가 후 개선과 재평가를 명시적으로 요청함

일반 교정·작성·요약·정리 요청에서는 점수표를 읽지 않는다.

## 4. 평가 대상과 수정 여부 표기

평가 결과에는 다음을 먼저 명시한다.

### `evaluate`

```text
작업 모드: evaluate
평가 대상: 현재 문서 원문
문서 수정 여부: 수정하지 않음
```

### `evaluate-and-improve`

```text
작업 모드: evaluate-and-improve
원문 평가 대상: 수정 전 현재 문서
수정본 평가 대상: 개선 후 문서
문서 수정 여부: 수정함
```

평가 대상이 파일 일부라면 `현재 문서 원문` 대신 실제 섹션이나 선택 범위를 적고 `부분 평가`라고 표시한다.

## 5. 평가 전에 수정하지 않기

`evaluate`와 `evaluate-and-improve`의 첫 평가는 현재 원문 그대로 수행한다.

- 맞춤법이나 사소한 오탈자도 점수 산출 전에 조용히 고치지 않는다.
- 평가 근거를 만들기 위해 문단 순서를 바꾸지 않는다.
- 추천 개선문을 원문으로 간주하지 않는다.
- 원문 평가가 끝나기 전에 파일 편집 도구를 호출하지 않는다.
- `evaluate-and-improve`에서도 원문 점수를 먼저 확정한 뒤 수정한다.

## 6. 점수를 계산하지 않는 경우

다음에는 숫자 대신 질적 판정만 제공한다.

- 문맥이 없는 한두 문장, 제목 또는 자막 한 줄
- 보호 영역이 대부분인 글
- 평가 기준을 적용할 정보가 부족한 문서 일부
- 사실·출처 충실성을 판단해야 하지만 기준 자료가 제공되지 않은 경우
- 전체 문서를 읽지 못했는데 전체 점수를 요청한 경우

사용자가 숫자를 요구해도 근거가 부족하면 임의의 총점을 만들지 않고 `부분 평가` 또는 `평가 보류`로 표시한다.

## 7. 필수 조건 상태

필수 조건은 다음 세 상태로 표시한다.

| 상태 | 의미 |
|---|---|
| `통과` | 확인 가능한 모든 필수 조건을 충족함 |
| `미통과` | 하나 이상의 필수 조건을 위반함 |
| `부분 확인` | 자료나 문맥 부족으로 일부 조건을 확인할 수 없음 |

### 필수 조건 G1–G7

| 코드 | 필수 조건 |
|---|---|
| `G1` | 사실, 수치, 날짜, 이름, 조건과 범위가 제공된 근거·요구사항과 충돌하지 않음 |
| `G2` | 긍정·부정, 가능·확정, 의무·권고의 정도가 명확하고 근거와 일치함 |
| `G3` | 핵심 정보의 누락이나 근거 없는 추가가 없음 |
| `G4` | 인용, 화자, 발언 주체, 관점과 출처 관계가 분명함 |
| `G5` | 코드, 링크, 경로, 고유명사, 표의 값 등 보호 영역이 온전함 |
| `G6` | 사용자가 지정한 방향, 말투, 고유 표현과 문서 목적을 훼손하지 않음 |
| `G7` | 치명적인 모호성, 문법 오류 또는 논리 충돌이 없음 |

### 모드별 적용

- `evaluate`: 현재 원문을 제공된 근거·요구사항과 비교한다. 근거가 없으면 외부 사실의 진위를 통과로 단정하지 않는다.
- `evaluate-and-improve` 원문 평가: 현재 원문을 같은 방식으로 평가한다.
- `evaluate-and-improve` 수정본 평가: 수정본을 원문 스냅샷, 제공된 근거와 요구사항에 함께 비교한다.

필수 조건이 `미통과`여도 `evaluate`에서는 문서를 수정하지 않는다. 현재 상태의 점수와 미통과 사유를 제시한다.

## 8. 공통 등급

각 항목은 다음 다섯 단계 중 하나로 판정한다. 근거 없이 중간 점수를 만들지 않는다.

| 등급 | 의미 | 20점 항목 | 15점 항목 | 10점 항목 | 5점 항목 |
|---|---|---:|---:|---:|---:|
| `A` | 목적에 적합하며 문제 없음 | 20 | 15 | 10 | 5 |
| `B` | 작은 문제가 있으나 사용에 지장 없음 | 16 | 12 | 8 | 4 |
| `C` | 의미는 통하지만 분명한 개선 필요 | 12 | 9 | 6 | 3 |
| `D` | 전달·사용을 방해하는 문제가 반복됨 | 8 | 6 | 4 | 2 |
| `F` | 항목의 목적을 충족하지 못함 | 0 | 0 | 0 | 0 |

### 등급 판단 원칙

- 단일 오탈자 하나로 항목 전체를 `D`로 내리지 않는다.
- 심각도, 반복 빈도와 문서 목적에 미치는 영향을 함께 본다.
- 동일 원인을 여러 항목에서 중복 감점하지 않는다.
- 문서 유형에서 허용한 표현을 공통 규칙만으로 감점하지 않는다.
- 확인하지 못한 사실을 추정해 점수를 높이지 않는다.

## 9. 총점 상태

모든 유형의 총점은 100점이다.

| 총점 | 품질 상태 | 의미 |
|---|---|---|
| 90–100 | 우수 | 현재 목적에 충분히 적합함 |
| 85–89 | 양호 | 경미한 개선 여지가 있음 |
| 75–84 | 개선 필요 | 주요 감점 항목의 개선이 권장됨 |
| 65–74 | 주요 개선 필요 | 정보 구조와 표현을 다시 검토해야 함 |
| 0–64 | 재구성 검토 | 원문 보호 범위 안에서 큰 폭의 개선이 필요함 |

85점은 권장 품질 기준점이다. 자동 수정 명령이 아니다.

- `evaluate`: 현재 점수를 그대로 보고하고 개선 가능 항목만 제시한다.
- `evaluate-and-improve`: 85점 미만 또는 유형별 하한 미달 항목을 개선 우선순위로 사용한다.
- 총점이 높아도 필수 조건이 `미통과`면 전체 상태를 통과로 표현하지 않는다.

## 10. 혼합 문서

주 유형 하나와 보조 유형 하나를 정한다.

- 점수는 주 유형 평가표로만 계산한다.
- 보조 유형은 필수 조건과 정확성 검토에만 사용한다.
- 두 유형의 점수를 평균하거나 합산하지 않는다.
- 기술 강의 대본은 `script`로 채점하고 `technical` 기준으로 식별자와 절차를 추가 검증한다.

## 11. 개선과 재평가

개선은 `evaluate-and-improve`에서만 수행한다.

1. 원문 점수를 먼저 확정한다.
2. 감점이 큰 항목과 필수 조건 문제를 개선 우선순위로 정한다.
3. 원문 보호 범위 안에서 한 차례 개선한다.
4. 수정본을 같은 기준으로 재평가한다.
5. 원문 점수, 수정본 점수와 변화량을 구분한다.
6. 수정본이 원문보다 의미 보존이 약하거나 점수가 낮으면 원문 또는 더 안정적인 버전을 유지한다.

`evaluate`에서는 점수가 낮아도 자동으로 고치지 않는다.

## 12. 출력 형식

### 평가만 수행한 경우

```markdown
작업 모드: evaluate
평가 대상: 현재 문서 원문
문서 수정 여부: 수정하지 않음
문서 유형: 조사·학습 자료
필수 조건: 통과
총점: 82/100 — 개선 필요

| 항목 | 점수 | 평가 근거 |
|---|---:|---|
| ... | ... | ... |

개선 가능 항목:
- ...
```

### 평가 후 개선한 경우

```markdown
작업 모드: evaluate-and-improve
원문 평가 대상: 수정 전 현재 문서
문서 수정 여부: 수정함
문서 유형: 조사·학습 자료
원문 필수 조건: 미통과
원문 점수: 72/100
수정본 필수 조건: 통과
수정본 점수: 89/100
점수 변화: +17

주요 개선:
- ...

최종 수정본:
...
```

### 비교 평가

```markdown
작업 모드: evaluate
평가 대상: 비교안 A / 비교안 B
문서 수정 여부: 수정하지 않음
```

각 안의 점수와 근거를 별도로 제시한다.
