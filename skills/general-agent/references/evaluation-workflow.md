# 평가·개선 작업 모드

점수 요청과 문장 수정 요청을 분리한다. 첫 점수의 평가 대상을 모호하게 만들지 않는다.

## 1. 작업 모드

| 모드 | 사용자 의도 | 동작 |
|---|---|---|
| `review` | 일반 검토·문제점·개선 방향 | 점수 없이 문제와 근거를 보고하고 수정하지 않음 |
| `evaluate` | 명시적인 점수·채점·등급 요청 | 현재 문서를 그대로 평가하고 수정하지 않음 |
| `improve` | 교정·수정·다듬기 | 점수 없이 최소 수정하고 역검증 |
| `evaluate-and-improve` | 평가 후 개선·수정 후 재평가 | 원문 평가 → 개선 → 수정본 재평가 |

## 2. 모드 판정

### `review`

검토, 문제점, 수정 방향, 제출 가능 여부, 최종 검수 또는 두 버전 비교를 요청했지만 점수·채점·등급을 요구하지 않은 경우 사용한다. 공통 기준과 해당 유형 기준으로 문제·근거·수정 방향만 보고한다. 파일을 수정하거나 점수표를 읽지 않는다.

### `evaluate`

점수·채점·등급을 명시적으로 요청한 경우에만 사용한다. 일반적인 “평가해 줘”는 별도의 채점 의도가 없으면 `review`로 처리한다.

평가 요청에 `수정`, `개선`, `반영`, `고쳐 줘`가 포함되지 않았다면 문서를 변경하지 않는다.

### `improve`

다음과 같이 수정 결과만 요청한 경우에 사용한다.

- 고쳐 줘
- 자연스럽게 다듬어 줘
- 문장을 교정해 줘
- 이 부분을 정리해 줘
- 점수 없이 수정해 줘

점수표를 읽지 않고 `BLOCK / FIX / REVIEW / KEEP`, 최소 수정과 역검증만 적용한다.

### `evaluate-and-improve`

채점과 수정을 함께 명시한 경우에만 사용한다. 예: “점수를 매긴 뒤 고쳐 줘”, “수정 전후 점수를 비교해 줘”. 검수 후 수정·반영 요청에 채점 의도가 없으면 `improve`를 사용한다.

명시적인 수정 의도가 없으면 이 모드를 선택하지 않는다.

## 3. `evaluate` 절차

1. 현재 문서를 평가 대상 원문으로 고정한다.
2. 평가 전에 문장, 파일 또는 구조를 수정하지 않는다.
3. 보호 영역과 평가 가능 범위를 확인한다.
4. 현재 문서에 필수 조건과 유형별 점수표를 적용한다.
5. 감점 근거와 개선 가능 항목을 정리한다.
6. 문서나 파일은 변경하지 않는다.

### 필수 출력 표기

```text
작업 모드: evaluate
평가 대상: 현재 문서 원문
문서 수정 여부: 수정하지 않음
```

파일 편집 도구, 패치 또는 YOLO 편집 블록을 출력하지 않는다.

## 4. `improve` 절차

1. 현재 문서를 원문으로 고정한다.
2. 보호 영역을 확인한다.
3. 공통 기준과 유형별 기준으로 문제를 판정한다.
4. 필요한 부분만 최소 수정한다.
5. 수정본을 원문과 역검증한다.
6. 사용자가 요청한 수정 결과만 제공한다.

점수, 등급과 통과 여부를 계산하거나 출력하지 않는다.

## 5. `evaluate-and-improve` 절차

1. 현재 문서를 원문 스냅샷으로 고정한다.
2. **수정 전에 원문을 먼저 평가한다.**
3. 원문 점수와 감점 근거를 기록한다.
4. 개선할 항목을 우선순위로 정한다.
5. 원문의 사실·의도·문체를 보호하며 한 차례 개선한다.
6. 수정본을 원문과 역검증한다.
7. 수정본을 같은 유형·같은 기준으로 재평가한다.
8. 원문과 수정본의 점수, 변화와 남은 문제를 비교한다.

원문 점수는 수정본을 보고 소급해 바꾸지 않는다.

### 필수 출력 표기

```text
작업 모드: evaluate-and-improve
원문 평가 대상: 수정 전 현재 문서
원문 점수: 82/100
수정본 점수: 91/100
점수 변화: +9
문서 수정 여부: 수정함
```

## 6. 비교 평가

둘 이상의 기존 문서를 일반 비교하는 경우 `review`를 사용하며 차이·근거·수정 방향만 제시한다. 비교 점수를 명시적으로 요청한 경우에만 `evaluate`를 사용한다.

- 각 문서를 수정하지 않고 같은 검토 기준으로 비교한다. 채점을 명시적으로 요청한 경우에만 같은 점수 기준을 적용한다.
- 문서별 강점과 약점을 비교한다.
- 사용자가 통합·수정까지 요청하면 채점 의도가 없을 때 `improve`, 채점도 요구했을 때 `evaluate-and-improve`를 사용한다.
- 비교 대상마다 평가 시점과 버전을 명시한다.

## 7. 평가 대상 고정

점수를 산출하기 전에 평가 대상을 명시한다.

- 현재 파일 원문
- 사용자가 붙여 넣은 원문
- 수정 전 버전
- 수정본
- 비교안 A / 비교안 B

평가 도중 문서가 바뀌면 같은 대상의 점수로 취급하지 않는다.

## 8. 개선점의 의미

`evaluate`에서 제시하는 개선점은 제안일 뿐이다.

- 개선점을 제시했다고 실제 문서를 수정한 것으로 보지 않는다.
- 추천 문장을 예시로 제시할 수 있지만 원문 파일에는 반영하지 않는다.
- 사용자가 개선을 승인하거나 요청하면 별도의 `improve` 또는 `evaluate-and-improve` 작업으로 수행한다.

## 9. 장문과 부분 평가

- 문서 일부만 읽었다면 `부분 평가`라고 표시한다.
- 읽지 않은 섹션을 포함한 전체 점수를 만들지 않는다.
- 일부 섹션을 수정한 뒤 전체 문서 점수라고 주장하지 않는다.
- 전체 재평가는 전체 문서를 다시 확인할 수 있을 때만 수행한다.
