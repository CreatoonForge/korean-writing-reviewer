# 일반 에이전트 긴 문서 처리 절차

문서 전체를 한 번에 안전하게 읽고 수정하기 어렵거나, 여러 섹션·표·코드·출처가 서로 연결된 경우 적용합니다.

## 1. 긴 문서 판정

다음 중 하나에 해당하면 긴 문서로 취급합니다.

- 여러 개의 큰 제목과 서로 다른 문서 유형이 섞여 있습니다.
- 보호 구문, 표, 코드, 인용과 출처가 많습니다.
- 전체 내용을 현재 문맥에서 읽을 수 없습니다.
- 한 번의 전체 수정으로 누락이나 구조 훼손 위험이 큽니다.
- 사용자가 장별·섹션별 검토를 요청했습니다.

고정된 글자 수만으로 판정하지 않습니다.

## 2. 전체 지도 작성

수정 전에 문서 전체에서 확인 가능한 범위를 읽고 내부 작업 지도를 만듭니다.

- 제목과 섹션 구조
- 문서의 주 유형과 보조 유형
- 주요 주장, 결론과 결정 사항
- 용어, 고유명사와 표기 기준
- 높임 수준과 종결형
- 인용·출처·코드·링크 등 보호 영역
- 섹션 간 의존 관계
- 현재 문맥에서 확인할 수 없는 부분

이 지도는 작업을 위한 내부 기준입니다. 사용자가 요청하지 않으면 별도 보고서로 출력하지 않습니다.

## 3. 분할 단위

- 제목 또는 의미가 완결되는 섹션 단위로 나눕니다.
- 문단 중간, 표 중간, 코드 블록 중간에서 자르지 않습니다.
- 앞뒤 섹션에 의존하는 정의·약어·지시어를 함께 확인합니다.
- 같은 용어와 주장이 흩어져 있으면 수정 전에 관련 위치를 찾습니다.

## 4. 섹션별 검토

각 섹션에서 다음 순서로 처리합니다.

1. 보호 영역 확인
2. 해당 섹션의 목적과 독자 확인
3. 공통 기준과 문서 유형 기준 적용
4. 최소 수정
5. 섹션 내부 역검증
6. 전체 문서 작업 지도에 용어·말투·결정 상태 반영

다른 섹션의 내용을 현재 문맥에서 확인할 수 없으면 추정해서 연결하지 않습니다.

## 5. 전체 일관성 검사

모든 섹션 수정 뒤 문서 전체에서 다음을 재검사합니다.

- 제목 단계와 섹션 순서
- 동일 개념의 용어 표기
- 인물·기관·제품·버전 이름
- 높임 수준, 시제와 종결형
- 중복된 결론과 상충하는 주장
- 표와 본문의 수치
- 링크, 각주, 인용과 참조 관계
- 정의·약어의 첫 등장 위치
- 결정·보류·미확정 상태의 일관성

섹션별 수정이 각각 자연스러워도 전체 문맥에서 충돌하면 해당 부분만 다시 조정합니다.

## 6. 도구와 문맥 제한

- 필요한 부분을 읽을 수 있는 파일 검색·읽기 도구가 있으면 사용합니다.
- 현재 문맥에 없는 앞뒤 내용을 추정하지 않습니다.
- 문서 전체를 읽지 못했다면 전체 검토를 완료했다고 주장하지 않습니다.
- 확인한 범위와 남은 범위를 사용자에게 명확히 알립니다.
- 일부 섹션만 읽은 상태에서 전체 문서 점수를 계산하지 않습니다.

## 7. 점수 평가

점수 평가 조건이 충족된 경우에도 다음 원칙을 지킵니다.

- 섹션별 점수를 단순 평균해 전체 점수로 만들지 않습니다.
- 전체 문서를 다시 읽을 수 있을 때만 최종 유형 점수를 계산합니다.
- 전체 문맥을 읽을 수 없으면 점수 대신 확인된 섹션의 질적 문제만 제시합니다.
- 점수 때문에 이미 확정한 섹션을 임의로 다시 쓰지 않습니다.

## 8. 파일 편집

- 한 번에 하나의 섹션 또는 명확한 최소 범위를 수정합니다.
- 여러 변경을 한 파일 전체 교체로 합치지 않습니다.
- 섹션별 수정 뒤 파일 구조와 보호 구문을 검증합니다.
- 마지막에 전체 문서의 일관성만 별도로 점검합니다.
