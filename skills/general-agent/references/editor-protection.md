# 일반 에이전트 파일·구문 보호 규칙

Claude Code, Codex, Hermes와 VS Code 기반 에이전트 등 일반 파일 편집 환경에서 적용합니다.

## 1. 편집 범위

- 선택 영역이 있으면 해당 범위만 수정합니다.
- 선택 영역이 없으면 사용자가 지정한 파일, 섹션 또는 문단만 수정합니다.
- 사용자가 전체 재작성을 요청하지 않았다면 파일 전체를 교체하지 않습니다.
- 여러 파일을 수정해야 한다면 각 파일의 필요성과 수정 범위를 먼저 구분합니다.
- 편집 도구가 있으면 해당 호스트의 최소 패치·편집 기능을 사용합니다.
- 편집 도구가 없으면 수정할 위치와 교체할 내용을 명확히 제시합니다.
- 특정 DSL, 패치 문법 또는 도구 이름을 모든 호스트에 강제하지 않습니다.

## 2. 원칙적으로 보호할 구조

사용자가 해당 구조의 변경을 요청하지 않았다면 내용 교정 과정에서 그대로 유지합니다.

### 문서 메타데이터

- YAML frontmatter의 경계 `---`
- 속성 이름, 들여쓰기, 배열·객체 구조
- 날짜, 식별자, 별칭, 태그와 상태 값
- TOML·JSON·XML 등 구조화된 메타데이터

일반 문장처럼 보이는 YAML 값도 설정·분류 정보일 수 있으므로 임의로 교정하지 않습니다.

### Markdown

- 제목 단계와 앵커
- 일반 링크와 참조형 링크
- 이미지·파일 링크
- 각주 정의와 각주 참조
- 인용문과 callout 형태
- 코드 블록의 언어 식별자
- 인라인 코드
- 체크박스 상태 `[ ]`, `[x]`, `[-]`
- 표의 파이프, 정렬 구문과 셀 수
- 강제 줄바꿈, 빈 줄, 들여쓰기와 중첩 목록
- HTML 주석

### 개발·기술 구문

- 코드, 명령어, 정규식과 쿼리
- 파일 경로, URL, 환경 변수와 설정 키
- 함수명, 클래스명, 타입명과 API 식별자
- 버전, 해시, 포트, 플래그와 매개변수
- Diff·patch의 문맥 줄과 기호
- Mermaid, PlantUML 등 다이어그램 코드
- HTML·JSX·TSX·MDX 태그와 속성
- 템플릿 변수와 자리표시자
- 로그와 오류 메시지 원문

코드 주석이나 문서 문자열을 교정할 때도 코드 구조와 이스케이프 문자를 보존합니다.

### 호스트별 문법

문서에 다음과 같은 전용 문법이 있으면 일반 Markdown 문장으로 바꾸지 않습니다.

- Obsidian 위키 링크와 임베드
- 블록 참조
- Dataview·DataviewJS
- 문서 생성기의 지시문
- 정적 사이트 생성기의 frontmatter와 shortcode
- 에이전트 또는 편집기용 마커

호스트 문법을 확실히 알지 못하면 보존하고 `REVIEW`로 남깁니다.

## 3. 수정 가능한 영역

다음 조건을 모두 충족하는 일반 자연어만 교정합니다.

- 보호 구문 밖에 있습니다.
- 사용자가 수정 대상으로 지정했습니다.
- 변경해도 링크, 코드, 데이터 구조와 식별 관계가 깨지지 않습니다.
- 앞뒤 문맥과 원문의 의미를 확인할 수 있습니다.

링크의 표시 문구만 수정하더라도 링크 대상과 앵커는 유지합니다.

## 4. 형식 보존

- 원본의 줄바꿈 방식과 들여쓰기 스타일을 유지합니다.
- 문단을 합치거나 나눌 때 제목, 목록, 표와 코드 블록의 경계를 확인합니다.
- 자동 포매팅이나 정렬을 문장 교정과 함께 수행하지 않습니다.
- 파일 인코딩과 줄 끝 문자를 임의로 바꾸지 않습니다.
- 변경 전후에 Markdown·코드 블록·태그의 열고 닫힘이 맞는지 확인합니다.

## 5. 최소 패치 검증

수정 후 다음을 확인합니다.

- 지정된 범위 밖의 내용이 바뀌지 않았습니다.
- 보호된 토큰과 구조가 동일합니다.
- 링크 대상, 코드 식별자, 표의 열 수와 체크박스 상태가 유지됩니다.
- 새 문법 오류나 렌더링 오류를 만들지 않았습니다.
- 전체 파일 교체가 필요하지 않았는지 다시 확인합니다.
