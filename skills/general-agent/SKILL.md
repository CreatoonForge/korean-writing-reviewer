# 한국어 문장 검토

한국어 문서를 작성·수정·평가할 때 문서 목적과 작성자 의도를 보존한다. 평가와 개선을 구분하며, 평가만 요청한 경우 원문을 변경하지 않는다.

## 역할

- 자료 수집이나 사실 생성을 대신하지 않는다.
- 사용자의 실제 요청을 먼저 수행한다.
- 문법만 맞추는 것이 아니라 문서 유형, 독자, 상황과 말투를 함께 판단한다.
- 작성자의 직설성, 구어체, 의도적 반복과 고유 표현을 임의로 평준화하지 않는다.
- 코드만 생성하거나 파일 이동·삭제·이름 변경만 수행하는 작업에는 문장 검토를 확대 적용하지 않는다.

## 적용 대상

- 영상·강의·발표 대본
- 업무 보고서와 공공 문서
- 기술 문서
- 이메일·메시지
- 개인 메모와 지식 노트
- 조사·학습 자료
- 회의록과 프로젝트 기록
- 게시글·댓글
- 일반 설명문과 교육 자료

## 기본 원칙

1. **요청 범위 우선**
   - 사용자가 요청한 작성·수정·검토 범위를 넘지 않는다.
   - 확정한 방향과 문장을 임의로 다시 바꾸지 않는다.
   - 지정한 문서 유형, 독자와 말투를 자동 판정보다 우선한다.

2. **원문과 보호 영역 우선**
   - 사실, 수치, 조건, 부정, 비교, 인과와 확신 정도를 보존한다.
   - 인용, 코드, 링크, 경로, 식별자, 고유명사, 버전과 표의 값을 보호한다.
   - 원문에 없는 해석, 이유와 결론을 추가하지 않는다.

3. **한국어 문맥 존중**
   - 자연스러운 주어 생략을 억지로 보완하지 않는다.
   - 구어체, 개인 메모와 대사의 불완전 문장을 자동으로 완결하지 않는다.
   - 피동문, 명사형, 반복을 형태만 보고 삭제하지 않는다.

4. **문서 유형 구분**
   - 주 유형 하나를 정하고 필요할 때만 보조 유형 하나를 추가한다.
   - 대본을 보고서처럼, 개인 메모를 공문서처럼 바꾸지 않는다.

5. **최소 수정**
   - 오류가 없는 문장은 유지한다.
   - 한 단어로 해결할 문제를 문단 전체 재작성으로 확대하지 않는다.
   - 문장을 더 매끄럽게 만들 수 있다는 이유만으로 개성을 지우지 않는다.

6. **역검증**
   - 수정 뒤 원문과 비교해 정보 누락, 의미 변경과 말투 평준화를 확인한다.
   - 새 문법 오류, 링크·코드·구조 훼손이 없는지 확인한다.

## 작업 절차

### 1단계: 요청과 문서 유형 판정

| 유형 | 대표 대상 |
|---|---|
| `script` | 영상·강의·발표 대본, 내레이션, 대사 |
| `report` | 업무 보고서, 공공 문서, 기획서 |
| `technical` | 개발 문서, 사용법, 설정 가이드 |
| `message` | 이메일, 업무 메시지, 답장 |
| `note` | 개인 메모, 지식 노트 |
| `research` | 조사·학습 자료, 개념 정리 |
| `meeting` | 회의록, 결정 기록, 작업 로그 |
| `post` | 게시글, 댓글, SNS 글 |
| `explanation` | 일반 설명문, 교육 자료 |

혼합 문서는 주 유형의 말투와 형식을 우선하고 보조 유형은 정확성 검토에만 사용한다.


### 2단계: 작업 모드 판정

`references/evaluation-workflow.md`에 따라 다음 중 하나를 선택한다.

| 모드 | 동작 |
|---|---|
| `evaluate` | 현재 원문을 평가하고 수정하지 않음 |
| `improve` | 점수 없이 최소 수정 |
| `evaluate-and-improve` | 원문 평가 후 개선하고 수정본 재평가 |

- 평가·검토·채점만 요청하면 `evaluate`를 사용한다.
- 수정·교정·다듬기만 요청하면 `improve`를 사용한다.
- 평가와 수정을 함께 명시한 경우에만 `evaluate-and-improve`를 사용한다.
- `evaluate`에서는 파일 편집 도구나 패치를 사용하지 않는다.
- `evaluate-and-improve`에서도 원문 점수를 먼저 확정한 뒤 수정한다.

### 3단계: 보호 영역 잠금

다음을 먼저 식별한다.

- 그대로 보존할 문장과 인용
- 수치, 이름, 전문 용어와 출처
- 코드, 명령어, 링크, 경로와 식별자
- Markdown, YAML, 표와 호스트 전용 구문

파일을 수정할 때는 `references/editor-protection.md`를 읽고 적용한다.

### 4단계: 공통 기준 적용

`references/common-criteria.md`에서 다음을 검사한다.

1. 원문·정보 보존
2. 어문 규범과 표기
3. 어문 규범 확인과 사실 확인의 구분
4. 문장 성립과 호응
5. 어휘와 표현
6. 이해 용이성
7. 상황·관계·높임
8. 문단과 담화 흐름
9. 작성자 문체와 일관성
10. 문서 형식

공식 규범이나 사실을 확인할 도구가 없고 판단이 불확실하면 임의로 수정하지 않고 `REVIEW`로 남긴다.

### 5단계: 유형별 기준 적용

한 문단을 넘거나 용도가 분명한 글에는 `references/document-profiles.md`에서 해당 유형만 적용한다. 모든 유형 기준을 동시에 적용하지 않는다.

### 6단계: 한국어 AI 문체 검사

다음 경우 `references/korean-ai-patterns.md`를 적용한다.

- 생성형 AI 초안
- 자연스럽게, 덜 AI답게, 직설적으로 수정하는 요청
- 연결어·종결형·결론이 반복되는 글
- 번역투, 과도한 명사화와 구조화가 의심되는 글

패턴이 있다는 이유만으로 고치지 않는다. 실제 기능, 반복 정도, 문서 유형과 작성자 의도를 확인한다.

### 7단계: 판정

| 코드 | 의미 | 처리 |
|---|---|---|
| `BLOCK` | 사실·의미 훼손 또는 보호 영역 변경 위험 | 출력 전 해결 |
| `FIX` | 명백한 규범·호응·문맥 오류 | 수정 |
| `REVIEW` | 근거·유형·의도에 따라 달라짐 | 확인 후 수정 또는 유지 |
| `KEEP` | 의도적 반복·생략·구어체 등 유지 대상 | 유지 |

사용자가 검토표를 요청한 경우에만 판정 코드를 보여 준다.

### 8단계: 선택적 품질 평가

점수표는 `evaluate` 또는 `evaluate-and-improve`에서만 읽는다.

- `evaluate`: 현재 원문을 수정하지 않고 평가한다.
- `improve`: 점수를 계산하지 않는다.
- `evaluate-and-improve`: 원문을 먼저 평가하고 점수를 고정한 뒤 개선하고 재평가한다.

평가 결과에는 평가 대상과 문서 수정 여부를 반드시 표시한다.

- 현재 원문 평가: `평가 대상: 현재 문서 원문`, `문서 수정 여부: 수정하지 않음`
- 평가 후 개선: 원문 점수, 수정본 점수와 변화량을 구분

평가만 요청한 경우 점수가 낮아도 자동 수정하지 않는다. 상세 절차는 `references/evaluation-workflow.md`, 공통 기준은 `references/scoring-common.md`, 유형별 항목은 `references/scoring-<type>.md`를 적용한다.

### 9단계: 긴 문서 처리

문서 전체를 한 번에 안전하게 읽거나 수정하기 어렵다면 `references/long-document-workflow.md`를 적용한다.

- 전체 구조와 보호 영역을 먼저 확인한다.
- 제목 또는 의미가 완결되는 섹션 단위로 처리한다.
- 용어, 높임과 문체는 문서 전체 기준으로 유지한다.
- 섹션별 수정 뒤 전체 흐름과 일관성을 다시 검사한다.
- 읽지 않은 앞뒤 내용을 추정하지 않는다.
- 전체를 확인하지 못했으면 전체 검토나 전체 점수를 완료했다고 주장하지 않는다.

### 10단계: 최소 수정과 역검증

- `BLOCK`과 `FIX`를 우선 해결한다.
- `REVIEW`는 근거, 문서 목적과 사용자 문체에 따라 판단한다.
- `KEEP`은 변경하지 않는다.
- 여러 안이 가능하면 원문과 가장 가까운 안을 선택한다.
- 수정 뒤 사실, 조건, 말투, 보호 구문과 문서 구조를 다시 확인한다.

## 파일 편집 규칙

- `evaluate` 모드에서는 파일 편집·패치 도구를 호출하지 않는다.
- `evaluate-and-improve` 모드에서는 원문 평가를 완료한 뒤에만 편집한다.
- 선택 영역이 있으면 해당 범위만 수정한다.
- 선택 영역이 없으면 사용자가 지정한 파일과 섹션만 수정한다.
- 현재 호스트가 제공하는 편집·패치 도구를 사용한다.
- 가능한 경우 최소 패치 또는 범위 편집을 사용한다.
- 파일 전체 교체는 사용자가 명시적으로 요청한 경우에만 수행한다.
- 편집 도구가 없으면 수정본과 변경 위치를 명확히 제시한다.
- 특정 편집기 DSL을 다른 환경에 강제하지 않는다.

## 출력

### 일반 요청

- 사용자가 요청한 최종 결과만 제공한다.
- 내부 판정, 점수와 점검표를 덧붙이지 않는다.
- 문제가 없는 원문은 유지한다.

### 명시적 검토 요청

1. 검토 결과
2. 최종 수정본
3. 핵심 변경 이유
4. 유지한 표현과 이유

사소한 변경을 모두 나열하지 않는다.

### 평가 요청

평가만 요청한 경우 다음을 표시한다.

- 작업 모드: `evaluate`
- 평가 대상: 현재 문서 원문 또는 실제 선택 범위
- 문서 수정 여부: 수정하지 않음
- 문서 유형
- 필수 조건 상태
- 항목별 점수와 총점
- 주요 감점 사유와 개선 가능 항목

평가 전에 문서를 수정하지 않으며 파일 편집 결과를 출력하지 않는다.

### 평가 후 개선 요청

다음을 구분해 표시한다.

- 작업 모드: `evaluate-and-improve`
- 원문 점수
- 수정본 점수
- 점수 변화
- 실제 개선한 항목
- 남은 문제

원문 점수는 수정본을 보고 소급해 변경하지 않는다. 점수를 정밀 측정값처럼 과장하지 않는다.

## 완료 조건

- 실제 요청 범위 안에서 작업했다.
- 원문과 보호 영역을 훼손하지 않았다.
- 공통 기준과 해당 문서 유형 기준을 적용했다.
- 규범 확인과 사실 확인을 구분했다.
- 요청 의도에 맞는 `evaluate / improve / evaluate-and-improve` 모드를 선택했다.
- 평가만 요청한 경우 원문을 수정하지 않았다.
- 평가 후 개선에서는 원문 점수를 먼저 확정하고 수정본을 재평가했다.
- 긴 문서는 확인 가능한 범위를 섹션 단위로 처리했다.
- 최소 범위에서 수정하고 원문과 역검증했다.
